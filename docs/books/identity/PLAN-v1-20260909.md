## 3. What the containment pass gives you as EVIDENCE (use this; do not re-derive it)

This is the part that makes a *confident* map possible rather than another scoring heuristic. The pass that
just finished did not only fix containment — it produced a labelled corpus about how each provider lies.

**3.1 — 8,511 judged issue ranges** (`CollectedEditionSpan` where `Source = 3` and `IssueStart IS NOT NULL`).
Each says: *this book collects issues #a-b of the run on this shelf.* That is a testable prediction about a
run's numbering. If a candidate ComicVine volume's issue list contains #a-b, the volume is evidence for that
run; if the volume tops out below #a, it is evidence against. **976 of these were read off the book's own
copyright page** and carry confidence ≥ 0.95 — treat those as ground truth for run identity.

**3.2 — 4,200 tombstones with reasons** (`Source = 3`, `IssueStart IS NULL`). Every one records *why* a
provider was wrong about a specific book. Mine `docs/books/containment/decisions/*.txt` — 976 files — and
`tools/pass2_flags.csv` (458 rows) for the vocabulary. The recurring shapes, each of which is a **feature
you can compute for any provider claim, on any entity**:

| shape | what it looks like | what it means |
|---|---|---|
| title-wide stamp | the same range on every volume of a title, or a one-issue `#N-N` on a 300pp book | the source keyed on the TITLE and returned the first record |
| hull | `#1-578`, `#1-1060`, `#0-619`, `#1-327` on a 326pp book | a list flattened into a span |
| wrong coordinate system | legacy numbering, `#1000000` (DC One Million), a chronology folder's SORT PREFIX, a YEAR | the source is answering about a different numbering |
| off-by-one-volume | LOCG gave Venom Vol. 06 the range that is Vol. 07's; gave the Zap volumes their neighbours' | the source's volume index is misaligned |
| matches our holdings | the claimed range equals exactly the files we happen to own | a coincidence that is a reason to **distrust**, not accept |
| crossover / anthology | Godhead, Realm of Kings, the JLU digests, War of the Realms | contents are a LIST of comics; no single range describes them |

**3.3 — 110 `conflated-series` flags** (`ContainmentFlag`, plus 420 `label-ambiguous`, 117
`overlap-in-series`, 29 `provider-disagrees`, 26 `duplicate-edition`). A conflated shelf holds several runs
that all number from #1. **These are precisely the shelves where a naive series↔volume match is wrong**, and
they are already identified. Feed the flag into matching as a hard gate, not a tiebreak.

**3.4 — corrected keys.** Issue numbers fixed by reading (chronology sort prefixes read as issue numbers,
title years read as issue numbers, sub-line `#N` read as issue numbers), and `IsCollection` / `Format` fixed
in both directions. **You must never match a trade against an issue record**; the flags are now right, so
use them.

**3.5 — the invariant style.** Four checks were written that find defects no queue could: `overclaim_check.py`
(does anything hold more than its book prints), `overlap_check.py` (can all the ranges on one shelf be true
at once), `audit_containment.py` (six structural invariants over the relationships that exist), and the
page-size guard now in `ContainmentJob`. **Write the identity equivalents in Phase 0 before you match
anything** — §7 names them.

## 4. Doctrine: how a match earns trust

Copied in spirit from PLAN.md §2 and §6.6, which held up across 976 shelves.

1. **Under-linking is safe; wrong-linking is not.** An unlinked item costs a row in a report. A wrongly
   linked one silently misattributes credits, tags, a cover and a rating, and corrupts any diff built on it.
   When in doubt, leave it unlinked and record why.
2. **A single uncorroborated provider claim is not evidence.** Store a link when **two independent legs
   agree**, or when **one leg agrees with something the collection itself asserts** (a judged range from
   §3.1, an ISBN/barcode, a ComicInfo `Web` id, a Calibre identifier).
3. **Corroboration must be independent.** LOCG and our own LOCG-derived spans are one source, not two.
4. **Record the evidence with the link, in words.** Every stored link gets a reason a person can check —
   the pass this plan follows wrote 976 such files and every disputed call was settleable because of it.
5. **Refusal is a first-class outcome** and must be counted, not silently skipped, so the remainder is
   always visible.
6. **Arithmetic beats assertion.** Page counts, issue counts, year ranges and run lengths killed more bad
   claims in the containment pass than any provider agreement confirmed. A CV volume with 4 issues is not
   our 50-issue run whatever the name says.

### The scoring model to build (Phase 0)
For each `(entity, provider record)` candidate, compute and STORE these, then decide from them:

```
name          normalised title match, and whether the year matches
year          |our YearStart - their start year|; a mismatch > 1 is a strong negative
count         our IssueCount vs their issue count; a ratio outside 0.5..2 is a strong negative
range         does any of our 8,511 judged ranges (§3.1) fall inside their issue list?
publisher     do they agree, once normalised through the Publisher table?
external      shared ISBN / barcode / ComicInfo Web id / Calibre identifier — the strongest signal
conflated     is the shelf flagged conflated-series? if so, series-level matching is BLOCKED (§3.3)
shape         does the claim have any §3.2 shape? each one is a veto, not a penalty
```
Accept on ≥ 2 independent positives and 0 vetoes. Everything else goes to a review queue **with its scores
visible**, so a human or a later reading pass settles it — that is how the containment pass got to zero.

## 6. Gotchas that will cost you a day each

**6.1 The Bash tool halves backslashes.** Windows/UNC paths and `\n` in `sed` lose a level. Multi-line
Python via a bash heredoc silently mangles or fails (`unexpected EOF while looking for matching '`) — it
cost two aborted batches in the last pass. **Write a `.py` file with the Write tool and run it**, or use the
PowerShell tool. Verify any path-carrying job with a prefix histogram.

**6.2 `Item.Path` ends in the FILE NAME**, not the folder. A manga volume file is named exactly like a run
folder, so search `segs[:-1]` only — otherwise One Piece becomes 103 series.

**6.3 Page-count arithmetic is the cheapest lie detector**, with three exceptions that are not lies:
`digital-mobile` / Infinity Comic / Webtoon rips inflate page count ~5× (one panel per page); prestige-format
issues are genuinely 48pp; an omnibus legitimately holds more than the run you are testing. `digital+` rips
open with black slipcase scans — front matter starts at p7. A Son of Ultron rip puts front matter one page
earlier than the Empire rip of the same trade.

**6.4 Two containment guards and one page-size guard live in `ContainmentJob.cs`** and were added
deliberately (PLAN.md §14.11, §14.13). Do not "simplify" them. Any change there must be followed by the
three standing checks in §8.

**6.5 `ItemProviderLink.Applied` is a v1 artefact** (§2). Do not gate on it.

**6.6 `Provider.Mu` is MangaUpdates, not Marvel.** Marvel is 6. The enum is
`Cv=0, External=1, Locg=2, Gcd=3, Mu=4, Barney=5, Marvel=6, Inducks=7`;
`LinkStatus = Pending 0, Matched 1, NoMatch 2, Multiple 3, Error 4, Manual 5, Cleared 6, Skip 7`;
`LinkQuality = Unknown 0, Low 1, Medium 2, High 3, Conflict 4`;
`EditionSource = Locg 0, Gcd 1, Cv 2, Curated 3`;
`TagSource = ComicInfo 0, Cv 1, Calibre 2, Locg 3, Gcd 4, External 5, Mu 6, AI 7`.

**6.7 Books (novels) are a separate key space.** `CanonicalKey = "book:" + …`, and every comic-identity
statement is narrowed off them by `SeriesResolver.NotBookSql`. Do not let comic matching touch them.

**6.8 `Series` is DERIVED.** Never edit `Item.SeriesId` directly — `books-resolve --series` will undo it.
The operator inputs are `ComicDetail.ParsedSeriesKey`, `SeriesKeyLink`, `Series.DisplayNameOverride`, and
the CV/External record names. `books-series-split` writes only `ParsedSeriesKey` for that reason.

**6.9 `SeriesTitle` is written by tooling, not the resolver.** `books-resolve --series` neither creates nor
clears `TitleId`; a split-created run inherits it; `build_titles.py` fills the rest. A batch verb must never
compute one identity per batch — that bug filed `G.I. Joe v2 (2001)` under the title `30 Days of Night`
(`repair_title_links.py` / `restore_franchise.py` exist because of it).

**6.10 One `calibre-debug` at a time**; Calibre path truncation at 34 chars, `PATH_LIMIT` 56 proven.

## 7. The phases

Each phase ends with an acceptance criterion phrased over the **population**, not the queue.

### Phase 0 — instrument before you touch anything (no writes)
Build `docs/books/identity/tools/`:
- `audit_identity.py` — the structural invariants, in the shape of
  `docs/books/containment/tools/audit_containment.py`. At minimum: no `Series.CvVolumeId` pointing at a
  missing `CvVolume`; no two file-holding `Series` sharing a `CvVolumeId`; no `ItemProviderLink` whose item
  is excluded or gone; no `SeriesTitle` orphan; `RunCount` agrees; no title whose runs disagree on
  franchise; no link on an item whose `IsCollection` contradicts the record's kind.
- `identity_coverage.py` — the §2 table, regenerated on demand, split by *file-holding* vs all.
- `candidate_score.py` — the §4 scoring model, read-only, emitting a scored candidate list.
- `candidate_report.py` — re-score `LinkCandidates` from our side and print the distribution of outcomes
  (accept / review / veto, and which veto), so Phase S's size is known before it starts. The schemas are in
  §2; they were opened while writing this plan and are what their names suggest.
> **Accept when:** `audit_identity.py` prints zero problems on today's data, and the coverage numbers in §2
> reproduce. If they do not reproduce, something changed — find out what before proceeding.

### Phase C — make ComicVine pay (the largest unused asset)
106,804 matched CV links produce 5 tags and 0 credits. Build the CV fold beside
`Resolve/LegsTagFoldJob.cs` (which does the GCD one and is the template): characters, teams, story arcs,
locations → `ItemTag` with `TagSource.Cv`; creators → `ItemCredit` with source Cv. Chunked, resumable,
dry-run first. `CvVolumeDescription` (119,879) is the synopsis source — check `SynopsisRules` in
`insights-and-kids.md` before writing any of it to a user-visible field.
> **Accept when:** `SELECT Source, count(*) FROM ItemTag GROUP BY 1` shows Cv in the same order of
> magnitude as its 106,804 links, `ItemCredit` likewise, and `audit_identity.py` is still zero.

### Phase S — series-level identity, corroborated (mostly consumption, not computation)
Do these in order; each one is cheaper than the last because of the one before.

**S1 — consume `LinkCandidates`.** 83% of our series keys already have scored CV candidates. For each,
re-score from our side using §4 (do **not** trust their `Score`: it is one source, and the whole lesson of
§3.2 is that one source is not evidence). The JSON carries `StartYear`, `Publisher` and `CountOfIssues`, so
the year, publisher and count tests run offline with no scraping. Veto on any §3.2 shape and on
`conflated-series`. Store accepted links with the reason; everything else to the review queue.

**S2 — give GCD a Series-level link.** There is none today. Follow `SeriesKeyLink(ParsedKey, Provider)`'s
existing shape; do not invent a third pattern. `books-gcd-match` already matches items by ISBN/barcode —
roll those item links up to a series majority as the seed, then extend by name/year/count.

**S3 — harvest the bridges for free.** With `GcdSeriesId` known, `LocgSeriesInference` (Support) and
`OlSeriesInference` (IsbnSupport) hand you LOCG and Open Library links **already corroborated by a count**.
Set a support floor, record it as the evidence, and treat anything below it as a candidate, not a link.

**S4 — the judged ranges as referee.** Where S1–S3 leave two candidates standing, test each against the
8,511 judged ranges (§3.1): a volume whose issue list does not reach our read `#a-b` is not our run. The
976 ranges read off a copyright page settle ties outright.

> **Accept when:** every file-holding `Series` either carries a link with a stored reason, or appears in a
> review queue with its scores — and the two sets sum to 41,092 with nothing in neither. Report the split
> by leg, and report how many links rest on **two or more** independent legs; that number is the honest
> measure of "confidently correct", not the total.

### Phase T — the Title tier, extended and enriched

4. Re-point the 6,253 titled-but-empty Series: find out whether they are split residue that should be

> **Accept when:** file-holding Series with a `TitleId` ≥ 90%, `PublisherId` set on every title whose runs
> agree, and zero titles whose runs disagree on franchise (that check passes today — keep it passing).

### Phase B — book-or-issue, and the partial rips
`docs/books/containment/tools/audit_issue_details.py` (the fifth standing check) reports **0 defects and
three LEADS** — populations that need better evidence than page count, not faults:

**453 — 250+pp files flagged as single ISSUES in a floppy publisher's folder. ALL 453 TITLES HAVE NOW BEEN
READ (2026-09-09) — do not re-read them.** The reading produced two things. First, 22 issue numbers lifted
straight from a title were cleared, and five of those sat INSIDE their own shelf's ladder where a future
range could have swept them: `Usagi Yojimbo - 35 Years of Covers` was issue #35, `Archie 1000 Page
Celebration` was #1000 on a shelf running 1-1000, `The Art of Judge Dredd - Featuring 35 Years` was #35,
`Iron Man 2020` was #2020, `X-Men '92` was #92. Second, the flag itself: the majority ARE collections, and
a real minority are not - original graphic novels (`Hound`, `Heavy Liquid`, `Super Spy`), art and reference
books (`The Art of Overwatch`, `Hyrule Historia`, `The Toys of He-Man`), newspaper strip volumes (17
`Superman Dailies`, `Popeye`, `Blondie`), magazines (three `Nintendo Power` issues at 270pp) and one mobile
rip (`G.O.D.S. - Infinity Comic 001`, 268pp because the format inflates ~5x).

**The flag was deliberately NOT bulk-flipped**, and the reason is worth keeping: `IsCollection` only has a
consequence through containment, none of the 453 nests anything or is nested by anything, and the check
suite confirms that. Flipping them changes no behaviour and no diff key; what a diff needs is the provider
record, which is this phase's actual job. So the reading is banked as evidence, not spent on a cosmetic
edit.

**The original wording, for context:** Reading them shows most are
plainly collections (`Hulk - Planet Hulk`, `Avengers vs. X-Men`, `Doom 2099 - The Complete Series`), but the
class is genuinely mixed and page count must not decide it: **Nintendo Power really is a 270pp magazine
issue**, and `G.O.D.S. - Infinity Comic 001` is ONE issue at 268pp because a mobile rip inflates page count
about fivefold (containment PLAN.md §14.12). This is a question the LEGS can answer — does the provider
record describe a collected edition? — which is why it lives here.

**906 — the same shape in a strip / OGN / manga folder, where `IsCollection = 0` is CORRECT.** A 365pp
`Dennis The Menace (2011)` is one year of daily strips; an original graphic novel has no constituent
issues; a manga volume is the unit. These were 906 of the 1,359 the check first reported as one
undifferentiated number, which is why the check is now category-aware. Do not "fix" them.

**583 — issue numbers that are not numbers, so no range can ever reach the file.** These are NOT parse
errors. `Flash v1 217 GL only` is a PARTIAL RIP — the Green Lantern story cut out of Flash #217 — and
`18 (GL I Only)`, `22 (Edit)` and 470 GCD `(X Story)` designations say the same thing: the leading number is
the issue, the parenthetical says this file is one story from it. **This is a schema decision for Eric, not
a data fix:** should `ComicDetail` carry a separate partial/story marker so `IssueNo` can be numeric? Until
it does, converting them buys a coordinate and loses the fact that the file is a fragment.

> Already fixed and not part of this phase: **431 issue numbers normalised** from `NN (of MM)` and the
> literal string `TPB` (2026-09-09). Those were genuinely uncomparable and the number was printed on the

> **Accept when:** the 453 are each corrected or classified with a provider-backed reason, the 583 have a
